# NAS 共享资料库

收藏、历史与观看进度保存到 SQLite；下载在独立 worker 中运行。收藏后抓取已有全集并持续追更，取消收藏会撤销播放权限、中断媒体响应、取消任务并删除该收藏代次的文件。电视已经缓冲的内容可能继续数秒。

普通 AES-128 HLS 按每个分片的原始媒体序号、密钥及 IV 解密后保存。保留 TS/fMP4、初始化文件、音轨、字幕及时间轴；不转码、不合并、不重新封装。清单改为本地地址并去掉已解除的加密标记。SAMPLE-AES/DRM、未完整结束的直播清单会明确拒绝。

本地文件只在全部下载并校验后发布。断点日志保存每个文件的 SHA-256 和长度；重试时校验已有文件，清单或密钥变更会使旧断点失效。后台任务用租约和收藏代次隔离，取消收藏或任务被接管后，旧 worker 无权创建或发布文件。

## 本地开发

使用 Node.js 22 或更高版本。两个进程必须使用相同的数据目录和媒体目录。

```sh
npm ci
npm run build:worker
# 在两个终端中传入同一组环境变量后分别运行：
npm run dev
npm run worker
```

环境变量：

- `PASSWORD`：访问密码，仍通过现有 Cookie 登录。
- `LIBRARY_DATA_DIR`：本地 SQLite 目录；缺省为项目下 `.libretv/`。
- `LIBRARY_MEDIA_DIR`：视频目录；缺省为数据目录下 `media/`。
- `LIBRARY_CONCURRENT_DOWNLOADS`：同时下载集数，默认 2，上限 4。
- `LIBRARY_REFRESH_MS`：追更间隔，默认 30 分钟，最低 1 分钟。
- `LIBRARY_MIN_FREE_BYTES`：剩余空间保留量，默认 64MiB。下载不设容量配额；空间不足时暂停任务并定期重试，不自动删除收藏。

修改下载引擎后重新执行 `npm run build:worker`。API 和 worker 必须运行相同版本。仅启动网页不会自动启动 worker，收藏页会显示后台未连接。

## NAS 容器准备

正式 NAS 配置位于相邻仓库 `docker-compose-pying/libretv/`，包括 Compose、部署脚本和外部环境模板。本轮只修改代码与配置，不执行部署。

该 NAS 配置沿用现有用户 brian（UID 1000 / GID 100），覆盖镜像默认的 1001。实际挂载路径、目录所有权、外部 env 文件及 Drone 发布步骤以该目录的 README 为准。SQLite 目录必须是 NAS 本机文件系统，不能是 SMB/NFS 共享挂载。将整个数据库目录持久化，包括 WAL/SHM。迁移、备份使用一致性 SQLite 备份或停机备份，不在运行中仅复制 `.sqlite` 主文件。

web 和 worker 使用同一镜像、同一组本地目录。新增依赖包含 SQLite 原生扩展，发布时需要对 NAS CPU 架构构建并验证。

## 页面与权限

- 播放页的“收藏并下载”将整部作品加入后台任务；“下载到设备”保留原浏览器导出功能。
- 收藏页显示全集下载进度、错误与重试，并支持继续播放。
- 已收藏作品进入资料库播放器；每次打开或换集时选择本地/在线，播放过程中不会因下载完成而自动换地址。
- iPhone/iPad 保持原生视频控件，Mac 保留 ArtPlayer；在线收藏播放也通过可撤销的资料库中转接口。
- 历史面板改为服务器共享记录，可手动导入浏览器旧历史；服务器已有记录不会被导入覆盖。
- 媒体签名限定到具体集与收藏代次。所有读取还检查当前收藏状态，取消后旧签名即使未到期也不可用。
- 清理失败会明确显示并由 worker 重试；再次收藏生成新代次，旧清理不会删除新文件。

关键测试在 `src/server/library/*.test.ts` 和 `src/server/download/*.test.ts`。本地 WebKit 与单元测试不等于手机到真实电视的 AirPlay 验收。
